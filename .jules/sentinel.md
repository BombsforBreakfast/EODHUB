## 2024-06-03 - Empty Expected Signature Authentication Bypass
**Vulnerability:** Found multiple instances where `crypto.timingSafeEqual` was used to compare HMAC signatures (e.g., `app/lib/server/arcadeAccess.ts`, `app/lib/server/loginMaintenanceGate.ts`, `app/lib/commerce/shopifyOAuth.ts`) where the expected signature string wasn't adequately verified to be non-empty before comparison.
**Learning:** `crypto.timingSafeEqual(Buffer.from(''), Buffer.from(''))` evaluates to `true`. If the expected signature string generator (e.g., `signPayload()`) returns an empty string (e.g. because the secret config is missing and defaults to `""`), comparing an empty user-provided signature to the empty expected signature via `timingSafeEqual` will return `true`, causing an authentication/authorization bypass.
**Prevention:** Always explicitly check for the presence/truthiness of the expected signature string (e.g., `if (!expected) return false;`) before converting to buffers and using `timingSafeEqual`.
